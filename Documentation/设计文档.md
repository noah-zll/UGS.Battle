# UGS.Battle 通用战斗框架设计文档

> 版本：0.1.0
> 包名：`com.ugs.battle`
> 命名空间：`UGS.Battle`
> 目标 Unity：2021.3+

---

## 1. 概述

`UGS.Battle` 是一个**与具体游戏解耦**的战斗框架底层库，为 Unity 项目提供属性（Attribute）、效果/Buff（Effect）、技能（Skill）、伤害结算（Damage Pipeline）、阵营关系（Faction）、战斗会话（Battle Session）与 AI 战术（Tactic）的标准运行时。

框架**不包含任何具体玩法规则**（不知道"棋子""骑兵""盾牌""灵根"是什么），所有玩法细节通过**注册表 + 策略接口**注入，从而：

- 同一套核心可同时驱动 **实时战斗**（场景内 60fps）与 **回合制后台模拟**（大世界低频结算）；
- 新增属性、新增效果、新增技能类型、新增伤害规则**无需修改包内代码**；
- 核心运行时为纯 C# 对象，不依赖 `MonoBehaviour`、不依赖 `UnityGameFramework`，可单元测试、可服务端复用、可战斗回放。

### 1.1 设计目标

| 目标 | 说明 |
|------|------|
| **玩法无关** | 包内不出现任何具体游戏的名词与枚举值；属性、效果、行为全部基于可扩展的 key/id |
| **可扩展** | 一切可替换点均为接口 + 注册表，扩展不需要改包 |
| **场景无关** | `Realtime` / `RoundBased` 两种 Tick 模式共用一套逻辑 |
| **确定性** | 内置可控随机源与执行顺序约束，支持回放、补算、联机校验 |
| **逻辑/表现分离** | 运行时只产出数据与事件，不触碰 GameObject / 动画 / UI |
| **可测试** | 核心不依赖 Unity 生命周期，可直接 NUnit 单测 |

### 1.2 非目标（边界）

- 不做寻路、不做动画、不做 UI、不做特效；
- 不做网络同步协议，只保证确定性以便上层复用；
- 不做配置表工具链（由 `UGF.GameFramework.Data` 或游戏侧负责烘焙成 Definition）。

**命名边界（硬性）**：包内**不得**出现具体游戏的专有名词与枚举值——包括但不限于
`Hp / Mana / Stamina（灵力/体力）/ 灵根 / 部位护甲 / 骑兵 / 盾牌 / 门派`。

| 游戏概念 | 包内的通用抽象 |
|----------|----------------|
| 生命 / 灵力 / 体力 | 资源型属性（`Define(..., isResource: true)`）+ `ResourceContainer` |
| 技能消耗灵力 | `SkillDefinition.Costs`（`ResourceCost` 列表） |
| 部位护甲 / 灵根加成 | `IAttributeFormula`（游戏侧实现） |
| 骑兵 / 盾牌 / 异常状态 | `IEffectBehavior` / `IDamageProcessor` / `ITactic`（游戏侧实现） |
| 门派 / 军队关系 | `FactionSystem` + `FactionRelation` |

> 评审门槛：任何 PR 若在 `Runtime/` 下出现上表左列的名词，直接打回。

## 3. 分层与数据流

```text
                        ┌──────────────────────────────┐
                        │        BattleSession         │  ← 顶层容器
                        │  Phase / Rules / Clock       │
                        └───────────┬──────────────────┘
             ┌──────────────────────┼───────────────────────┐
             ▼                      ▼                       ▼
    ┌────────────────┐    ┌──────────────────┐    ┌──────────────────┐
    │  FactionSystem │    │  DamagePipeline  │    │  TacticScheduler │
    │  阵营关系图     │    │  伤害处理器链     │    │  AI 战术调度      │
    └────────────────┘    └──────────────────┘    └──────────────────┘
             ▲                      ▲                       │
             │                      │                       ▼
    ┌────────┴──────────────────────┴───────────┐   ┌───────────────┐
    │              ICombatUnit                  │   │ UnitCommand   │
    │  ┌─────────────┐  ┌──────────────────┐   │   └───────────────┘
    │  │AttributeCont│  │  EffectContainer │   │
    │  │ 属性 + 缓存  │  │ Buff/Debuff 实例  │   │
    │  └─────────────┘  └──────────────────┘   │
    └───────────────────────────────────────────┘
```

**核心约束（必须遵守）：**

1. **单向数据流**：`Tactic → UnitCommand → 表现层执行 → 命中回调 → DamagePipeline → ICombatUnit.ApplyDamage → Effect/Attribute 变化 → BattleEvent`。
2. **运行时不自持 Unity 对象**：`ICombatUnit` 不暴露 `GameObject`、`Transform`；位置以 `Vector2` 快照形式提供。
3. **一切"顺序"必须显式**：伤害处理器有 `Order`、效果 Tick 按注册顺序、事件按订阅顺序。

## 4. 核心基础设施

### 4.1 BattleClock — 战斗时钟

```csharp
namespace UGS.Battle.Core
{
    /// <summary>战斗内部时间轴。所有计时（冷却、Buff 持续时间、DoT 间隔）都基于此，
    /// 而非 UnityEngine.Time，以保证暂停/倍速/回放一致。</summary>
    public sealed class BattleClock
    {
        public float Elapsed { get; private set; }      // 累计战斗时间
        public float DeltaTime { get; private set; }    // 本帧步长
        public float TimeScale { get; set; } = 1f;
        public bool Paused { get; set; }

        public void Advance(float realDeltaTime)
        {
            if (Paused) { DeltaTime = 0f; return; }
            DeltaTime = realDeltaTime * TimeScale;
            Elapsed += DeltaTime;
        }
    }
}
```

### 4.2 BattleRandom — 确定性随机

战斗结果必须可复现（回放、后台补算、回归测试）。**禁止**在战斗逻辑中使用 `UnityEngine.Random` / `System.Random`。

```csharp
namespace UGS.Battle.Core
{
    public sealed class BattleRandom
    {
        private ulong _state;

        public BattleRandom(ulong seed) => _state = seed == 0 ? 0x9E3779B97F4A7C15UL : seed;

        public ulong NextULong()      // xorshift64*
        {
            _state ^= _state >> 12;
            _state ^= _state << 25;
            _state ^= _state >> 27;
            return _state * 0x2545F4914F6CDD1DUL;
        }

        public float NextFloat() => (NextULong() >> 40) / (float)(1UL << 24);
        public float Range(float min, float max) => min + NextFloat() * (max - min);
        public int Range(int minInclusive, int maxExclusive) => minInclusive + (int)(NextULong() % (ulong)System.Math.Max(1, maxExclusive - minInclusive));
        public bool Chance(float probability) => NextFloat() < probability;
        public int NextInt(int maxExclusive) => Range(0, maxExclusive);

        public ulong State => _state;
        public void Restore(ulong state) => _state = state;   // 快照/回放
    }
}
```

> 每个 `BattleSession` 持有独立 `BattleRandom`；单位、效果、管道都通过 `BattleContext.Random` 取随机，禁止各自 new。

## 5. 属性系统（Attributes）

### 5.1 设计要点

- **属性 key 由字符串定义**，运行时映射为紧凑 `int`，避免包内出现固定枚举；
- 三层数值来源：**Base（基础值）**、**Modifier（修正层，带来源）**、**Formula（后处理公式）**；
- 每个属性独立缓存 + 脏标记；`DamageReductionRate → 各部位减伤` 这类**跨属性依赖**通过 `IAttributeFormula` + `MarkDirty` 传播解决。

### 5.2 定义与注册

```csharp
namespace UGS.Battle.Attributes
{
    public enum ModifierOp { Add, Multiply, Override }

    public sealed class AttributeDefinition
    {
        public int Id;
        public string Key;              // "attack" / "crit_rate" / "head_reduction"
        public float DefaultValue;
        public float Min = float.MinValue;
        public float Max = float.MaxValue;
        public int Order;               // 计算顺序（依赖关系用）

        /// <summary>是否为"资源型"属性：有独立的当前值，可被消耗/恢复。
        /// 包内不预设任何具体资源名（生命/法力/体力/怒气…），仅据此分配资源槽位。</summary>
        public bool IsResource;
    }

    public static class AttributeRegistry
    {
        private static readonly Dictionary<string, AttributeDefinition> ByKey = new();
        private static readonly Dictionary<int, AttributeDefinition> ById = new();
        private static int _nextId = 1;

        public static AttributeDefinition Define(string key, float defaultValue = 0f,
            float min = float.MinValue, float max = float.MaxValue, bool isResource = false)
        {
            if (ByKey.TryGetValue(key, out var exist)) return exist;

            var def = new AttributeDefinition
            {
                Id = _nextId++, Key = key, DefaultValue = defaultValue, Min = min, Max = max,
                IsResource = isResource
            };
            ByKey[key] = def;
            ById[def.Id] = def;
            return def;
        }

        public static AttributeDefinition Get(string key) => ByKey[key];
        public static AttributeDefinition Get(int id) => ById[id];
        public static bool TryGet(int id, out AttributeDefinition def) => ById.TryGetValue(id, out def);
    }
}
```

> 属性的**增减逻辑**（例如 `CriticalDamage` 基础 150%、`CooldownReduction` 上限 80%）不写在包里，而是由游戏侧通过 `IAttributeFormula` 或 `Define(min,max)` 配置。

### 5.3 修正器（Modifier）

```csharp
namespace UGS.Battle.Attributes
{
    /// <summary>属性修正来源。一个来源（装备 / Buff / 天赋）可同时修正多个属性。</summary>
    public interface IAttributeModifier
    {
        object Source { get; }                       // 用于按来源批量移除
        IEnumerable<int> AffectedAttributes { get; }
        ModifierOp Op { get; }
        float GetValue(int attributeId, in AttributeQueryContext ctx);
    }

    public readonly struct AttributeQueryContext
    {
        public readonly ICombatUnit Owner;
        public readonly int AttributeId;
        // 游戏侧可读的外部因素（等级、装备、状态），由 Owner 提供
        public readonly object Extra;
    }

    /// <summary>最常用实现：固定值 / 百分比修正。</summary>
    public sealed class AttributeModifier : IAttributeModifier
    {
        public object Source { get; }
        public ModifierOp Op { get; }
        public float Value { get; }
        private readonly int[] _targets;

        public AttributeModifier(object source, ModifierOp op, float value, params int[] attributeIds)
        { Source = source; Op = op; Value = value; _targets = attributeIds; }

        public IEnumerable<int> AffectedAttributes => _targets;

        public float GetValue(int attributeId, in AttributeQueryContext ctx)
            => System.Array.IndexOf(_targets, attributeId) >= 0 ? Value : 0f;
    }
}
```

### 5.4 属性容器

```csharp
namespace UGS.Battle.Attributes
{
    public sealed class AttributeContainer
    {
        private readonly ICombatUnit _owner;
        private readonly BattleServiceRegistry _services;
        private readonly Dictionary<int, float> _base = new();
        private readonly Dictionary<int, List<IAttributeModifier>> _modifiers = new();
        private readonly Dictionary<int, float> _cache = new();
        private readonly HashSet<int> _dirty = new();
        private readonly Dictionary<int, List<int>> _dependents = new();   // 依赖反向索引

        public event System.Action<int, float /*old*/, float /*new*/> Changed;

        public AttributeContainer(ICombatUnit owner, BattleServiceRegistry services);

        public float GetBase(int attributeId);
        public void SetBase(int attributeId, float value);          // 标记脏 + 传播依赖

        public void AddModifier(IAttributeModifier modifier);
        public void RemoveModifier(IAttributeModifier modifier);
        public void RemoveModifiersFrom(object source);             // Buff 过期时批量清理

        public float Get(int attributeId);
        public void MarkDirty(int attributeId);
        public void MarkAllDirty();

        /// <summary>声明依赖：when attributeId 变化时，dependent 也需要重算。</summary>
        public void AddDependency(int attributeId, int dependentAttributeId);
    }
}
```

**`Get` 计算流程：**

```text
1. 命中缓存 → 直接返回
2. base = Base[id]（未设置则用 Definition.DefaultValue）
3. 遍历该属性全部 Modifier：
     Add      → sum += value
     Multiply → mul *= (1 + value)
     Override → override = value（最后一个生效）
4. value = override ?? (base + sum) * mul
5. 依次执行该属性的 IAttributeFormula（Order 升序），可读取其他属性（递归 Get + 缓存）
6. Clamp 到 [Definition.Min, Definition.Max]
7. 写缓存、清脏标记、触发 Changed
```

### 5.6 与"资源值"（当前生命 / 法力 / 体力…）的边界

**资源 = 带"当前值"的属性**（可被消耗或恢复）。包内**不预设任何具体资源名**：
`hp` / `mana` / `stamina` / 怒气 / 护盾池 / 灵力，全部由游戏侧自行 `Define(..., isResource: true)` 声明。

包只提供两样东西：

| 组成 | 职责 |
|------|------|
| `AttributeDefinition.IsResource` | 标记哪些属性需要分配"当前值"槽位 |
| `ResourceContainer` | 当前值存取、上限查询、变化钳制，统一触发资源变化事件 |

```csharp
namespace UGS.Battle.Units
{
    /// <summary>通用资源池。按属性 Id 索引，包内不认识"生命""法力"这类具体概念。</summary>
    public sealed class ResourceContainer
    {
        public ResourceContainer(AttributeContainer attributes);

        public float GetMax(int resourceAttributeId);       // = Attributes.Get(id)
        public float GetCurrent(int resourceAttributeId);
        public float GetRatio(int resourceAttributeId);     // Current / Max，Max=0 时返回 0
        public void  SetCurrent(int resourceAttributeId, float value);

        /// <summary>增减并钳制到 [0, Max]，返回实际变化量（用于吸血/溢出统计）。</summary>
        public float Change(int resourceAttributeId, float delta);
        public bool  IsDepleted(int resourceAttributeId);
    }
```

### 6.1 分层

| 层 | 类型 | 职责 |
|----|------|------|

### 6.2 定义

```csharp
namespace UGS.Battle.Effects
{
    [System.Flags]
    public enum EffectTag
    {
        None        = 0,
        Buff        = 1 << 0,
        Debuff      = 1 << 1,
        Control     = 1 << 2,   // 硬控（眩晕/冰冻）
```

> 因此由容器在 `Apply` 时按 key 逐实例创建；定义本身保持纯数据、可共享、可缓存。

### 6.6 叠加与移除规则

| StackRule | 重复施加 | 层数变化 | 时长 |
|-----------|----------|----------|------|
| `Independent` | 新建实例 | 各自独立 | 各自计时 |
| `Refresh` | 复用实例 | 不变（增加 `+1` 上限到 MaxStacks 则叠层） | 重置为 Duration |
| `Stack` | 复用实例 | `min(stacks, MaxStacks)` | 重置为 Duration |
| `Extend` | 复用实例 | 不变 | `Remaining += Duration` |
| `Ignore` | 丢弃 | — | — |

移除顺序：`OwnerDied → Manual → Dispelled → Expired`；同帧内按 `ApplyOrder` 逆序移除，保证表现稳定。

### 6.7 包内自带行为

| `PeriodicDamageBehavior` | 每 `Period` 造成伤害（DoT） |
| `PeriodicHealBehavior` | 每 `Period` 治疗（HoT） |
| `ShieldBehavior` | 提供可吸收伤害的护盾池，优先被 `ShieldAbsorbProcessor` 消耗 |

### 8.3 包内处理器

| Order | 处理器 | 职责 |
|-------|--------|------|
| 0 | `AccuracyProcessor` | 命中判定（命中率由 `Payload` 提供，未命中→`Blocked`+`Halted`） |
| 10 | `CriticalProcessor` | 暴击判定与倍率（不可暴击/概率 0 时跳过） |
| 20 | `MitigationProcessor` | 通用减伤（护甲/抗性，按 `DamageKind` 走 `IDamageKindHandler`） |
| 30 | `ShieldAbsorbProcessor` | 护盾吸收（先单位护盾池，再 Buff 护盾） |
| 40 | `ClampProcessor` | 上下限（最小 1 / 测试用固定值 / PvP 修正） |
| 100 | `ApplyDamageProcessor` | 将最终伤害写入 `Target.PrimaryResourceAttributeId` 对应资源，由 `ICombatUnit.IsAlive` 判定存活，发 `DamageDealtEvent` / `UnitDiedEvent` |

> **顺序语义**：`Order` 越小越先执行。游戏侧插入自定义处理器时，使用 0~100 之间的小数/整数空缺位（如 25 插入部位减伤）。

```csharp
        InProgress,     // 进行中
        Resolving,      // 结算中（失败方溃败/撤退表现）
        Ended,          // 已结束
    }

    public enum BattleTickMode
    {
        Realtime,       // 每帧驱动，表现层同步（细节地图）
        RoundBased,     // 按固定间隔推进若干"回合"（大世界后台模拟）
    }

    public enum BattleEndReason { Victory, Draw, Timeout, Aborted, AllDefeated }
}
```

转换规则（唯一合法路径）：

```text
Created    → Preparation   : Start()
Preparation→ InProgress    : SetReady() / 准备完成
InProgress → Resolving     : 胜利条件满足
InProgress → Ended         : Abort()
Resolving  → Ended         : 结算表现完成
```

**Tick 分派逻辑：**

```csharp
public void Tick(float realDeltaTime)
{
    if (Phase != BattlePhase.InProgress && Phase != BattlePhase.Preparation) return;

    Clock.Advance(realDeltaTime);

    if (Rules.TickMode == BattleTickMode.Realtime)
    {
        // 1. 效果计时（Buff/DoT）
        foreach (var unit in Factions.AllUnits) unit.Effects.Tick(Clock.DeltaTime);
        // 2. AI 决策（产出 Command 给表现层）
        Tactics.Tick(this, Clock.DeltaTime);
        // 3. 技能冷却推进
        foreach (var skill in AllSkillRuntimes) skill.Tick(Clock.DeltaTime);
    }
    else // RoundBased
    {
        _roundAccumulator += Clock.DeltaTime;
        while (_roundAccumulator >= Rules.RoundInterval)
        {
            _roundAccumulator -= Rules.RoundInterval;
            RunOneRound();     // 批量结算：所有单位按顺序出手一次 + 效果 Tick 一次
        }
    }

    // 4. 胜利判定
    if (Rules.VictoryCondition.Evaluate(this, out var winner, out var reason))
        EnterResolving(winner, reason);

    // 5. 超时
    if (Rules.MaxDuration > 0 && Clock.Elapsed >= Rules.MaxDuration)
        EnterResolving(-1, BattleEndReason.Timeout);
}
```

> `Realtime` 模式下 AI 只产出 `UnitCommand`，**不直接改位置**；`RoundBased` 模式下由 `RunOneRound()` 内部直接结算伤害（无表现层）。

约定：

- 战术**只做决策**，不执行移动/攻击；
- 战术可按兵种实现（游戏侧用 `ITactic` 自己判断 `UnitType`），包内不引入兵种概念；
- 战略 AI（聚类集火、绕后、撤退）与战术 AI 都实现 `ITactic`，通过 `Priority` 组合。

### 11.1 命令执行契约（ICommandExecutor）

战术产出的是"意图"，把意图变成动作是宿主的事。包只负责把命令交付出去：

```csharp
public interface ICommandExecutor
{
    void Execute(BattleSession session, IReadOnlyList<UnitCommand> commands);
}

public sealed class BattleSession
{
    public ICommandExecutor CommandExecutor { get; set; }
}
```

| 项 | 约定 |
|---|---|
| 回调时机 | 每轮战术结算结束（`TickTactics`），`RoundBased` 与 `Realtime` 走同一个入口 |
| 空列表 | **也会回调**。这是宿主判定"上一轮命令失效"的唯一信号 |
| 有效期 | 命令只对"本轮"有效，下一轮重新产出 |
| 列表所有权 | `commands` 由包复用，下一轮先 `Clear`；跨帧保留必须自行拷贝 |
| 未注册 | `CommandExecutor == null` 时不回调，行为与"没有战术"完全一致 |
| 抢占 | `ITacticOutput.IsClaimed` 只解决包内争抢；命令与宿主自身 AI 的冲突由宿主在执行器里裁决 |

**为什么执行不放进包里**：`MoveCommand` 要变成一次寻路、`AttackCommand` 要变成一次状态切换，
必然依赖引擎的导航 / 动画 / 状态机。这些包内既没有，也不应该有 —— 放进来的代价是包被引擎绑死。

同理，命令的**权威性**（是建议还是强制）属于宿主策略：
包不规定"收到 `MoveCommand` 就必须移动"，只保证"这一轮谁被下达了什么命令"是清晰且可复现的。

### 11.2 命令的适用层级（重要约束）

`UnitCommand` **只承载战略级意图**，不承载战术级决策：

| 层级 | 典型决策 | 频率 | 归属 |
|---|---|---|---|
| 战略级 | 集火哪个方向、从哪一侧包抄、是否分兵 | 0.5 ~ 1 秒 | 包内 `ITactic` → `UnitCommand` |
| 战术级 | 这一帧打谁、什么时候放技能、是否后撤 | 每帧 ~ 0.05 秒 | 宿主状态机（规则可用包内纯函数保证一致） |

**原因**：`BattleSession` 在 `RoundBased` 模式下每 `RoundInterval`（默认 1 秒）才跑一次 `TickTactics`。
把帧级决策塞进来，会让"每 0.05 秒重算一次的目标"退化成"1 秒更新一次"，比宿主自己算更差；
而 `Realtime` 模式下会话内要同时维持两套时钟（回合结算 vs 战术频率），复杂度收益不成正比。

**因此实现 `ICommandExecutor` 时，不要照着 `UnitCommand` 的枚举一个个去接。**
`AttackCommand` / `CastSkillCommand` / `HoldCommand` / `RetreatCommand` 目前的定位是
"战略级意图的预留描述"：只有当某条战术真正能在战略层决定"打哪个方向""什么时候集体撤退"时，
才去实现对应的执行逻辑 —— 在此之前它们没有产出方，实现了也是死代码。

判断标准很简单：**这条决策需要多单位协同、且容忍 0.5 秒以上的延迟吗？**
答"是"就适合做成 `UnitCommand`；答"否"就留在宿主，用包内纯函数约束规则。

## 14. 配置烘焙（Definition 构建）

包内 `Definition` 是**运行时对象**，不直接序列化；由上层把配表转换成 Definition。


## 16. 性能设计与约束

> 本章为**强制约定**，不是建议。违反即视为不符合包规范。

### 16.1 性能预算

| 指标 | 目标 | 采集方式 |
|------|------|----------|
| 200 单位、60fps 战斗逻辑（`Tick` 全链路） | < 2 ms/帧 | `ProfilerMarker` 分段 |
| 单次 `DamagePipeline.Process`（10 个处理器） | < 0.02 ms | 批量 10k 次取均值 |
| 稳态 GC Alloc（战斗中任意 10 秒窗口） | **0 B** | `ProfilerRecorder(GC.Alloc)` |
| K-Means 聚类（N=200） | < 1 ms/次，0 Alloc | 同上 |
| 500 单位属性容器常驻内存 | < 300 KB | 内存快照 |
| 世界地图 30 场并行后台结算 | < 0.5 ms/帧均摊 | 同上 |

### 16.2 强制数据结构约束

**1）属性容器必须数组化**

```csharp
public sealed class AttributeContainer
{
    private readonly float[] _base;    // index = attributeId
    private readonly float[] _cache;
    private readonly byte[]  _dirty;   // 0=干净 1=脏
    private readonly int     _capacity;
}
```

- `AttributeRegistry` 保证 id 从 1 **连续递增**；启动期 `AttributeRegistry.Seal()` 一次性确定容量并预分配。
- **禁止** `Dictionary<int,float>` 出现在 `Get` 热路径。

**2）单位必须 Slot 化**

```csharp
public sealed class SlotTable<T> where T : class
{
    private T[] _items;
    private int[] _generation;      // 防悬空句柄
    private int   _count;

    public int  Add(T item);
    public bool TryGet(int slot, int generation, out T item);
    public void Remove(int slot);
    public ReadOnlySpan<T> AsSpan();   // 连续内存遍历
}
```

- `BattleSession.Tick` 遍历单位用 `for` + `AsSpan()`，**禁止** `foreach (var u in Factions.AllUnits)`。
- `UnitId → slot` 的字典只在注册/注销时使用，不进帧循环。

**3）效果集合必须 O(活跃效果) 到期**

```csharp
public void Tick(float deltaTime)
{
    if (_count == 0) return;                                  // 空容器早退（关键）

    for (int i = 0; i < _active.Count; i++)                   // 仅活跃效果
        _active[i].Step(deltaTime);

    while (_expiry.TryPeek(out var e, out var remain) && remain <= 0f)   // 到期最小堆
        Expire(_expiry.Dequeue(), EffectRemoveReason.Expired);
}
```

**4）空间查询必须走索引**

```csharp
public interface ISpatialIndex
{
    void Rebuild(ReadOnlySpan<ICombatUnit> units);
    int  Query(Vector2 center, float radius, int factionId, List<ICombatUnit> results);
    ICombatUnit FindNearest(Vector2 from, int factionId, float maxRadius);
}
```

- 包内提供 `UniformGridSpatialIndex`（2D 均匀网格，格边长 ≈ 2×最大攻击范围）。
- `BattleRules.SpatialIndex` 可替换；`FactionSystem.QueryHostileInRange` / `FindNearestHostile` **必须**走索引，禁止全表扫描。
- 重建频率由 `BattleScheduler` 控制（默认 5 帧），支持增量更新。

**5）热路径禁用清单（Code Review Checklist）**

| 禁止 | 原因 | 替代 |
|------|------|------|
| `Where / OrderBy / ToArray / Average` | 迭代器 + 数组分配 | `for` + 预分配缓冲 |
| 闭包 lambda 订阅 | 每次 new 委托 | 缓存方法组 / 字段委托 |
| 字符串拼接、`ToString()` 进战斗日志 | 每命中一个 string | `BATTLE_DIAGNOSTICS` 宏 + `[Conditional]` |
| `foreach` 遍历 `IEnumerable<T>` | 可能装箱 / 迭代器分配 | `for` + 索引或 `Span` |
| `Vector2.Distance` | 多余开方 | `sqrMagnitude` |
| `GetComponent / Find / Camera.main` | 全局查找 | 初始化期缓存 |
| `Guid` / `DateTime.Now` | 分配 + 不确定性 | `BattleRandom` / `BattleClock` |

### 16.3 零分配命中路径

| 对象 | 做法 |
|------|------|
| `DamageContext` | `BattleBufferPool` 池化（同 Session 单线程，嵌套深度 ≤ 2） |
| `DamageStep` 日志 | 仅 `BATTLE_DIAGNOSTICS` 宏下编译；Release 用 `[Conditional]` 空实现 |
| `DamageResult.Steps` | 池化 `List<DamageStep>`，Release 下直接 `null` |
| 事件对象 | `BattleEventBus` 内部泛型池；高频事件可改 struct + 静态订阅表 |
| 临时集合 | `BattleBufferPool.RentList<T>()` + `try/finally` 归还（禁止 `new List`） |
| 飘字 / 特效 | 包内不产生，由游戏侧池化 |

```csharp
public sealed class DamageContextPool
{
    private readonly Stack<DamageContext> _pool = new(4);
    public DamageContext Rent(BattleSession session, in DamageRequest request);
    public void Return(DamageContext ctx);   // 清空 Steps / Payload / 引用字段
}
```

### 16.4 执行顺序：注册期排序，运行期只遍历

| 位置 | 规则 |
|------|------|
| `DamagePipeline` | `Add` 时按 `Order` **插入有序**（或 `Seal()` 时一次性 `Sort`）；`Process` 内只 `for` |
| `EffectContainer` | `Apply / Remove` 时维护 `ApplyOrder` 有序；`Tick` 内不排序 |
| `AttributeContainer` | 公式链在注册/`AddDependency` 时排好序；`Get` 内不排序 |
| `TacticScheduler` | `Register` 时按 `Priority` 排序；`Tick` 内不排序 |
| `BattleEventBus` | 订阅时生成调用列表快照（cached array），仅订阅变动时重建；`Publish` 遍历数组 |

> **反例（禁止）**：`foreach (var p in _processors.OrderBy(p => p.Order))` —— 每次伤害一次 LINQ 排序 + 迭代器分配。

### 16.5 BattleScheduler：分层频率

```csharp
public sealed class BattleScheduler
{
    /// <summary>注册一个调度层。phaseOffsetMs 用于错峰，避免多层同帧撞车。</summary>
    public void Schedule(string key, float interval, int phaseOffsetMs, Action<float> tick);
    public void Tick(BattleClock clock);   // 只执行本帧"到期"的层
}
```

推荐分层（`BattleRules` 可配）：

| 层 | 频率 | 内容 |
|----|------|------|
| L0 | 每帧 | 效果计时、技能冷却、伤害应用 |
| L1 | 每 2~3 帧 | 目标重选、攻击位释放检查 |
| L2 | 每 5 帧 | 空间索引重建、范围标志刷新（`hasEnemyInRange`） |
| L3 | 每 0.5s | AI 聚类 / 战术决策 |
| L4 | 事件驱动 | 属性重算（脏标记）、效果过期、死亡处理 |

### 16.6 事件分级

| 级别 | 语义 | 派发时机 | 默认 |
|------|------|----------|------|
| `Critical` | 阶段变更、单位死亡、战斗结束、技能施放 | 立即 | 开 |
| `Normal` | 伤害、治疗、效果施加/移除 | **帧末批量**（`Flush`） | 开 |
| `Diagnostic` | 属性变化、效果 Tick、处理器步骤 | 立即 | **关** |

`BattleEventBus.Flush()` 在 `Tick` 末尾统一派发 `Normal` 事件：减少跨模块随机访问的 cache miss，并让表现层天然可合并（同单位同帧多段伤害合并飘字）。

### 16.7 并行与确定性边界

```text
只读阶段（可并行 / Burst）             写入阶段（必须串行）
├── 空间索引查询、范围筛选              ├── 伤害应用（资源写入）
├── 聚类、目标评分                      ├── 效果增删
├── 属性 Get（缓存只读）                ├── 位置提交
└── 快照读取                            └── 事件入队（非派发）
```

- **双缓冲位置**：`_posRead[]` / `_posWrite[]`，帧末一次 swap → 只读阶段无写冲突。
- **随机数单源**：并行阶段**禁止**消费 `BattleRandom`（顺序不确定）；需要随机的评分改用确定性哈希（`unitId ^ frameIndex`）。
- `BattleSession.Tick` 不调用任何 Unity API → 可整体移出主线程，配合固定步长（`1/30`）保证确定性。

### 16.10 优化优先级与红线

| 优先级 | 内容 |
|--------|------|
| **P0** | 属性数组化、效果到期堆、命中零分配、注册期预排序、空容器早退 |
| **P1** | `BattleScheduler` 分层、事件批处理、Slot 化遍历、空间索引 |
| **P2** | 双缓冲 + 只读阶段 Burst 并行、逻辑移出主线程 |

**红线：**

1. 不为性能破坏确定性（并行只允许发生在只读快照上）；
2. 不在包内引入 Unity 物理 / 渲染 / UI 依赖；
3. 不为微优化牺牲接口清晰度——**先测量，再优化**，无基线不动手。

## 18. API 速查

```csharp
// 1. 启动期：定义属性 + 注册扩展
var hp     = AttributeRegistry.Define("hp", 100f, 0f, isResource: true);    // 资源型（生命）
var mana   = AttributeRegistry.Define("mana", 0f, 0f, isResource: true);    // 资源型（法力，游戏自定义）
var attack = AttributeRegistry.Define("attack", min: 0f);                    // 普通属性
BattleServiceRegistry.Default.RegisterAttributeFormula(attack.Id, new WeaponAttackFormula());
BattleServiceRegistry.Default.RegisterEffectBehavior("attr", def => new AttributeModifierBehavior(def));
BattleServiceRegistry.Default.RegisterTargetSelector("all_enemy_in_range", new AllEnemiesInRangeSelector());

// 2. 建会话
var session = new BattleSession(new BattleRules
{
    TickMode = BattleTickMode.Realtime,
    RandomSeed = 12345,
});
session.Factions.CreateFaction(1);
session.Factions.CreateFaction(2);
session.Factions.SetRelation(1, 2, FactionRelation.Hostile);

// 3. 注册单位
session.RegisterUnit(1, myKnight);
session.RegisterUnit(2, enemyArcher);

// 4. 装技能
var skill = new SkillRuntime(new SkillDefinition
{
    Id = 1001,
    Cooldown = 3f,
    Costs = { new ResourceCost(mana.Id, 10f) },   // 消耗 10 点 "mana"（由游戏定义）
    Selector = new CurrentTargetSelector(),
    Actions = { new DamageAction { Multiplier = 1.2f, Kind = DamageKind.Physical } },
});
myKnight.Skills.Add(skill);

// 5. 推进
session.Start();
session.SetReady();
session.Tick(UnityEngine.Time.deltaTime);

// 6. 订阅事件（表现层）
session.Events.Subscribe<DamageDealtEvent>(e => ShowFloatText(e.Request.Target, e.Result.FinalAmount));

// 7. 直接结算一次伤害（不走技能）
session.Damage.Process(new DamageRequest
{
    Attacker = myKnight, Target = enemyArcher, Amount = 25f, Kind = DamageKind.Physical
}, session);
```
